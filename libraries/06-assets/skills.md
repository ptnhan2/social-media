## stock-sourcing-usage
**Summary:** Tool selection guide between Pexels and Pixabay for stock images/videos based on need (quality vs category filtering vs color matching), with full input parameter schemas. Covers license safety (both free, commercial, no attribution required), rate limits, and gotchas (expiring Pixabay URLs, 1280px resolution cap, Pexels auth header). Stock assets integrate into the asset manifest identically to generated ones with provenance metadata.
**Key numbers/params:**
- pexels_image/video: 200 req/hr; pixabay_image/video: 100 req/min
- Pixabay standard API max 1280px wide (largeImageURL); full res needs approved access
- Pexels: 28 locales; per_page 1-80; video preferred_quality hd/sd; image download_size original/large2x/large/medium
- Pixabay: query max 100 chars, image_type all/photo/illustration/vector, video_type all/film/animation, 20 categories, editors_choice, safesearch
- Duration filtering: min_duration/max_duration to avoid oversized downloads
- Cost: $0.00 both providers; licenses: free commercial, no attribution, cannot sell unaltered / imply endorsement
**Actionable rules:**
- Download Pixabay immediately after search — URLs expire; never cache them
- Pixabay searches are deterministic — if result is bad, change keywords, don't retry same query
- Pexels uses bare API key in Authorization header (not Bearer) when debugging
- Use duration filters to avoid downloading 30s clips when 4s needed
- Record provenance (photographer, source_url, license) in asset manifest metadata

## image-gen-usage
**Summary:** FLUX image generation workflow for video frames: resolutions must be multiples of 16 (max 4MP), with a 3-part contextual prompt construction (scene shot language + adapted playbook anchor + concrete scene description) instead of copying the playbook prefix verbatim. Visual consistency via a hero reference image (I2I), shared visual system, and seed locking. Batch strategy: hero at max quality → iterate with klein → final pass with pro, at known per-image costs.
**Key numbers/params:**
- FLUX resolutions: 1920x1088 (16:9), 1088x1920 (9:16), 1024x1024 (square), 1280x720 (thumb); must be multiples of 16, max 4MP
- Cost: pro $0.03/img, max $0.07, klein $0.015; 8-image explainer budget ≈ $0.43
- FLUX.2 references: up to 4 (klein), 8 (pro/max/flex); rate limit 24 concurrent requests
- Prompts: keep to 2-3 sentences; adapted style anchor 5-10 words
- Fallback template order: style anchor → scene description → lighting → composition → camera (photoreal only) → aspect ratio
**Actionable rules:**
- Design the shared visual system first (mood, texture, palette, lighting, rendering medium), adapt per scene — never paste image_prompt_prefix verbatim
- Generate hero at max quality first, use as input_image for all subsequent frames (consistency)
- Never request text in images — add text as overlays in compose stage; avoid detailed hand poses
- Use seed locking only as supplement (fragile to prompt changes)
- Estimate total cost before generating; switch to local diffusers if over budget

## bg-remove-usage
**Summary:** Background removal as an asset-prep step before compose: model selection by subject type (u2net default, u2net_human_seg for people, isnet-general-use for complex edges), with alpha matting only for hair/fur/foliage. Output transparent PNG for compositing flexibility or bg_color for brand-consistent solid backgrounds. Includes quality checklist for edge halos and residual bleed.
**Key numbers/params:**
- Runtime: ~1-3s/image CPU, <0.5s GPU (onnxruntime-gpu); alpha matting ≈ 2x processing time
- Install: `pip install rembg` (CPU) or `pip install rembg[gpu]` (CUDA)
- Models: u2net (default, fast), u2net_human_seg (people), isnet-general-use (complex edges, slower)
**Actionable rules:**
- Any frame containing people → u2net_human_seg (tighter masks)
- Enable alpha_matting only for hair, fur, foliage; disable for products/text/logos (hard edges correct)
- Output transparent PNG (omit bg_color) for compositing; set bg_color to playbook background token for solid replacements
- Process source frames BEFORE compose stage (asset-prep, not compose-time)
- Check edges at full resolution before compositing — halo/bleed must be caught early

## broll-planning
**Summary:** Decide stock vs generated by scene reality: real-world/people/archival → stock; abstract concepts, diagrams, branded style → generated. Extract B-roll needs from script sections into a B-Roll Brief (scene, need, source, keywords, duration, orientation, mood, fallback). Stock queries should be 2-4 keywords led by subject, always with a POV keyword (drone/OTS/macro/top-down/locked-off) — POV mismatch is more costly to fix than color grade. Score results 1-5, use 3+.
**Key numbers/params:**
- Query template: `[subject] [attribute] [POV]` — e.g. "tokyo skyline night drone", "scientist microscope OTS"
- Clip duration: 4-6s typical B-roll; video must be ≥ scene need (can trim, can't extend)
- Scoring heuristic: 5 perfect, 4 minor crop, 3 acceptable+grade, 2 marginal, 1 wrong; threshold 3+
- Image criteria: 1080p minimum for video frames, no watermarks, POV match
- Both Pexels and Pixabay free for commercial use, no required attribution
**Actionable rules:**
- Do: add a POV keyword to every stock query; ask the director if scene implies no POV
- Do: failure chain — retry synonyms → other provider → AI generation → only then escalate to user
- Do: track photographer/source_url/license in asset manifest
- Don't: use queries with >4 keywords; crop your way out of a wrong POV
- Don't: mix stock and generated styles within one scene

## upscale-usage
**Summary:** Upscaling is asset-prep, done BEFORE compose. Default `RealESRGAN_x4plus` at 4x; anime/motion-graphics frames use `RealESRGAN_x4plus_anime_6B`; prefer 2x over 4x when source is already 720p. Enable `face_enhance` (GFPGAN) only when faces are present. Never upscale beyond 4x in one pass, never denoise above 0.8.
**Key numbers/params:**
- Scales: 4x (480p→1080p, 720p→4K), 2x (720p→1080p); max 4x per pass
- Models: `RealESRGAN_x4plus` default, `RealESRGAN_x4plus_anime_6B` (flat color), `RealESRNet_x4plus` (fastest)
- denoise_strength: 0.5 clean digital, 0.6 light artifacts, 0.7-0.8 old/noisy; hard cap 0.8
- Video upscale is 5-10x real-time on GPU; 4x upscale ≈ 16x file size
- AI image frames: generate at 512-1024px then upscale; keep denoise 0.5
**Actionable rules:**
- Do: upscale before compose; use anime model for Manim/flat illustration frames
- Do: budget pipelines — upscale only hero shots + thumbnails
- Do: inspect for hallucinated detail, over-sharpening, face distortion
- Don't: upscale already-1080p/4K sources; enable face_enhance without faces; exceed 4x/0.8

## image-provider-usage
**Summary:** Provider selection by scene type: real-world photos → stock (pexels/pixabay, free); hero images and abstract concepts → `flux_image`; text-in-image and complex instructions → `openai_image` (GPT Image 2 best text rendering); logo/brand → `recraft_image` (SVG); edits/composites → `grok_image`. `image_selector` routes automatically; override with `preferred_provider` or restrict with `allowed_providers` (free/local). Recraft V4's `style` param currently causes 422 errors — encode style in the prompt text instead.
**Key numbers/params:**
- Costs: flux $0.03-0.05/img, grok $0.02/output + $0.002/input edit, openai $0.01-0.21, recraft $0.04-0.25, pexels/pixabay free, local free
- Production paths (10 images): premium ~$0.35, standard ~$0.25, budget $0.00, offline $0.00
- Fallback chains: real photo pexels→pixabay→flux; diagram diagram_gen→flux; edit grok→openai; text openai→recraft
- Use `generation_mode="edit"` to route only to edit-capable providers
**Actionable rules:**
- Do: use Remotion `text_card` instead of AI images for verbatim text (CTA screens, business names, phone numbers)
- Do: color-grade everything (stock + generated) with the playbook LUT for consistency
- Do: adapt playbook mood/palette into scene-specific anchors, don't paste a prefix
- Don't: mix styles within one scene (all stock or all generated); use `image_gen` (deprecated)

## explainer/asset-director
**Summary:** Produces every asset from the scene plan (narration, images, diagrams, code, music) and verifies each file exists with quality checks. Mandates budget check before generation, sample-preview approval per expensive asset type (TTS/image/music) to prevent wasted spend, and a CHAI-style 3-pass prompt self-review (pre-caption → critique against 5-aspects → post-caption). Music failure must be reported, never silently deferred.
**Rules we should adopt:**
- Inventory asset tasks from scene plan (scene_id, type, tool, estimated_cost) + narration (per section), music (1 track), optional SFX.
- Check budget BEFORE generating: sum estimated costs vs remaining; if over, route to cheaper providers, reduce image count, or skip optional assets.
- Sample preview to prevent wasted spend: TTS sample (from most demanding section), image sample (most representative scene), music sample — max 3 iterations per type before escalating; costs ~$0.03-0.08 to prevent $1-3 waste.
- TTS generation: apply delivery_cues/provider_text; map cues to provider params (OpenAI: instructions only w/ gpt-4o-mini-tts; Google: ssml + speaking_rate 0.25-2.0; ElevenLabs: stability/similarity_boost/style/speed); verify duration ±15%.
- Flat-voice failure rule: if approved voice sounds monotone/rushed/ignores pauses, do NOT batch — fix voice_performance params and regenerate sample.
- Image prompts built from scene purpose (shot language + adapted visual anchor + concrete subject), consistency anchors applied but NOT identical phrasing per image (same prefix everywhere = machine-made feel).
- Music priority: user-selected library track → user music_library → generation API (check registry status first, skip immediately if unavailable) → log `music_status: "unavailable"` with reason. Never produce video silently without music.
- CHAI 3-step prompt self-review before every generation prompt: draft → critique (5-aspects: specified? confusable terms disambiguated? emotional adjectives replaced with visual causes? consistency anchors verbatim across shots?) → rewrite. Log pre/critique/post triplet.
- Mid-production fact verification: web-search actual appearance of real places/people/objects before generating images — don't trust model training data.
- Verify every asset exists on disk + narration durations ±15% + sample settings match batch + visual consistency + budget.
- Never AI-generate images with verbatim text (CTA, names, contact, legal) — use text_card.
**What we already do differently:**
- We already do per-sentence TTS with open/norm/punch/question tagging + cost per sentence, Pixabay-first assets with license gates, and rembg cutouts. We don't do the sample-preview approval loop or the CHAI 3-pass prompt review — both are cheap adoptions. Music priority + explicit failure reporting aligns with our Pixabay-free-first path.

## longform-educational/asset-director
**Summary:** Voice consistency is THE #1 longform rule: all 12 chapters of narration must use the identical voice identity — pass exactly the same provider settings to every TTS call, verify programmatically, no per-chapter tuning. Narration timing is probed per chapter and fed back to the EP (narration > planned ×1.05 → rewrite chapter). Asset volume is managed per chapter with checkpoints; cheap assets (Pixabay over AI) preferred for filler.
**Rules we should adopt:**
- Voice consistency enforcement: read voice_identity from script metadata; identical provider_settings on EVERY TTS call; compare programmatically (don't eyeball); record `voice_consistency.identical_settings = true`; mismatch = revise assets.
- Language param: ALWAYS set `language` (e.g. `"vi"`) with eleven_v3 for non-English; never auto-detect; verify voice supports it before committing.
- Per-chapter timing: probe EVERY narration file duration; compute per-chapter totals; flag chapters where narration > planned ×1.05 (EP sends back for rewrite); re-gen a chapter's narration requires re-probing duration (re-gen changes the slot, cascades to edit).
- Sample preview for longform: ONE sample from the opening chapter's hook section (most performance-sensitive); approve once; then batch all chapters with identical settings — don't re-ask per chapter.
- Asset volume (12 chapters): 36-60 images, 48-96 narration files; generate/verify/checkpoint per chapter (partial_progress).
- Style consistency across batches: same visual anchors in every prompt; chapters generated on different days must not look like different videos.
- Prefer cheap: stock (Pixabay/Pexels) over AI for filler scenes, diagrams over generated images for data scenes.
**What we already do differently:**
- We already use per-sentence ElevenLabs TTS with recorded params + Pixabay-first assets; the identical-settings-across-all-chapters verification and per-chapter duration feedback loop are the longform additions to adopt.

## animation/asset-director
**Summary:** Prefers deterministic assets over high-variance generation (diagram_gen before generic images, math_animate for real math, provided art first). For image-based animation, generates 2-3 images per scene using a reusable VISUAL SYSTEM (anchors kept in metadata) + nearby seed values for natural crossfade, tests one image first, then batches idempotently, and COPIES assets to Remotion's public/ directory (the #1 render-failure cause). Builds reusable systems (typography, lower-thirds, motifs) once.
**Rules we should adopt:**
- Deterministic-first: diagram_gen before generic image gen, code_snippet for code scenes, math_animate for real math motion, provided artwork before new generation.
- Sample preview: TTS sample (strongest pacing/emotional section) + one visual sample before batching; max 3 iterations; don't batch until approved.
- Multi-image generation workflow (image_animation): define a VISUAL SYSTEM (reusable anchors, e.g. "hand-painted nature fantasy, warm moss-and-amber palette, soft diffused light") → adapt per scene (wide establishing / close beat / abstract reveal) → use nearby seeds (100, 101) for A/B variants of the same prompt = subtle differences = natural crossfade → generate ONE test image at final res first → batch (skip existing = idempotent) → copy to `remotion-composer/public/<project>/`.
- Reusable systems built once: typography treatments, lower-third/label styles, repeated motif assets, background containers.
- Narration optional but the plan must be explicit: narration-led / text-led / music-led stated in metadata; narration-led applies voice_performance + delivery cues.
- Consistency ≠ same prompt every time: keep a recognizable world while letting each beat feel fresh.
- Pitfalls: high-variance gen when deterministic works, rebuilding the same title/label system repeatedly, hiding failed asset paths, treating TTS as raw text-to-audio (needs pauses/emphasis cues).
**What we already do differently:**
- We already enforce "copy vs import" discipline via `shared/layouts/` + `shared/primitives.tsx`. The public/ staging + seed-management crossfade recipe is new and applies if we adopt anime_scene.
