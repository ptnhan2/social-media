1. Timeline quá trình (đúng những gì user sẽ trải nghiệm)

Bước 1 — Mở app
Mở picker → thấy 8 projects (test projects lẫn thật) → click "🎬 Video mới từ ý tưởng". OK nhưng hơi rối.
Bước 2 — Đặt slug
Nhập legacy-code-signs → tạo. Friction nhỏ: đáng lẽ auto từ idea.
Bước 3 — Nhập ý tưởng + shape
CreateCard với 4 shape presets — rất tốt, chọn Hook 30s · 4 beats, mô tả expectation rõ ràng.
Bước 4 — Gửi agent
Prompt tự điền đầy đủ (idea verbatim + shape + từng bước có điểm dừng). Click Send.
Bước 5 — Research: 25+ PHÚT & kẹt ⚠️
Agent chạy → 5 phút lang thang grep mã nguồn → dispatch subagent → subagent ERROR → agent bỏ cuộc âm thầm. Tôi phải tự nhận diện lỗi + restart server + nhắn retry.
Bước 6 — Research card
Sau restart: 5 sub-questions · 20 findings · 15 sources. Insights mạnh ("legacy code là mismatch, không phải tuổi"; "senior devs viết legacy code nguy hiểm nhất"). Duyệt.
Bước 7 — Story: phải nhắn lại ⚠️
UI nói "agent SẼ compose story" nhưng không có gì chạy — phải mở drawer nhắn agent. Story nhận được: xuất sắc (thumbnail promise: "Brand-new code. Already legacy. 3 signs — and sign #3 is written by your senior dev, not the intern.")
Bước 8 — Script (~10 phút)
Click nút "📝 Viết script →" (affordance tốt lần này). Agent đọc treatments rồi viết: 4 beats chuẩn hook — question → reframe → 3 signals → twist, tự chọn 4 treatments khác nhau.
Bước 9 — Generate (~8 phút)
Confirm dialog rõ (4 beats, ước tính 4-8 phút, cost-aware). Voice + timeline + render chạy một mạch. QC: 3/4 pass, beat 3 fail (narration 10.08s vs 7.6s plan).
Bước 10 — Xem video + duyệt
Candidate video playable 36.8s. QC badges đỏ trên beat 3. Nhập note → Redo ✓.
Bước 11 — Editor
Mở editor: hoàn hảo — 4 beat clips + 4 voice clips sync + treatments render trên canvas + beat markers mô tả narrative.
Bước 12 — REDO cycle: 12+ phút chưa xong ⚠️
Nhắn agent xử lý REDO → agent lang thang đọc projects khác (agent-loop-test docs), 12+ phút không ra kết quả.

3. Chưa tốt — xếp theo mức độ ảnh hưởng user

🔴 CRITICAL — user thật sẽ kẹt

#1. LangGraph server chạy code cũ → agent mất tool mới → chết âm thầm.
Server boot 13:54 chiều 30/08, tool research_topic code lúc 21:00 tối — agent nhận prompt "dùng research_topic", không thấy tool trong session, grep mã nguồn 5 phút tìm cách gọi, dispatch subagent (cũng không có tool) → ERROR → IDLE không lời giải thích. Fix: (a) Runbook thêm rule "restart langgraph sau khi thêm/sửa tool"; (b) langgraph dev cần verify tool list; (c) health-check tool registration ở /ok.
#1b. Agent đọc STALE MIRROR của workspace — không thấy file studio vừa ghi (được xác nhận bằng evidence).
Tôi ghi REDO vào qa/approval.json lúc 19:16 UTC (status changes_requested + note đầy đủ — verify trên disk). Agent trả lời: "approval.json: pending, note rỗng, cập nhật lần cuối 29/08" và đoán "workspace này là mirror của máy Windows, snapshot cuối ~17:59 UTC". Nghĩa là: file writes từ studio KHÔNG đến tay agent kịp thời — agent quyết định trên data cũ, tự nhận xét "note không khớp mô tả của bạn". Agent thậm chí confuse với agent-loop-test (có "rút gọn beat 3" y hệt từ walkthrough hôm qua — trùng hợp gây tin nhắn hallucination-ish). Đây là nguyên nhân sâu của "agent lang thang": nó investigative vì dữ liệu nó thấy mâu thuẫn với yêu cầu. Fix: đồng bộ filesystem view giữa studio và agent tools (cùng process filesystem hoặc watch-sync tức thời); tối thiểu agent phải verify freshness (mtime) trước khi kết luận "không có".
#2. Agent dead-end sau lỗi — không message lỗi, không retry guidance.
Sau khi task ERROR, drawer chỉ hiển thị chip "ERROR" kỹ thuật. Không có "Research failed — bấm retry" hay lý do. User không biết下一步 làm gì. Fix: AgentPanel bắt task ERROR → hiển thị message thân thiện + nút retry.
#3. Approval checkpoint KHÔNG trigger agent — "agent SẼ làm X" là lời hứa rỗng.
Duyệt research → không có gì chạy. Duyệt story → may mắn có nút "Viết script →" (prefill prompt, nhưng user vẫn phải bấm Send). REDO → không có affordance nào. Tôi phải tự nhắn agent 3 lần trong 1 walkthrough. Fix: approval action tự gửi continuation message cho agent (cùng cơ chế prefill nhưng TỰ ĐỘNG), hoặc studio hiển thị rõ "nhắn agent tiếp tục: [nút]".

🟡 MAJOR — tốn thời gian, gây mất niềm tin

#4. Agent loop inefficiency khi conversation dài.
REDO đơn giản (rút gọn 1 beat + regen 1 voice) — agent 12+ phút lang thang đọc editor docs của PROJECT KHÁC (agent-loop-test) mà chưa hành động. Context dài làm agent lost. Fix: system prompt chặt hơn (chỉ project hiện tại), hoặc REDO message tóm tắt context gọn (task-focused continuation thay vì append vào conversation dài).
#5. Project mới có beat rác từ createBlankProject.
"Target shape: 1 beats · 5s target" hiển thị SAI (đã chọn Hook 4 beats/30s) vì blank edit-doc có 1 beat rác 5s transcript rỗng. Fix: blank project beats: [] hoặc lưu shape vào state khi create.
#6. Subagent delegation sai tầng.
Agent dispatch subagent để chạy tool có sẵn trong toolset của chính nó (research_topic nằm trong tools list). Subagent không có tool → ERROR. Fix: system prompt: "gọi tool trực tiếp; subagent chỉ cho việc phức tạp cần context riêng".

🟢 MINOR — polish

#7. Duration input step="0.5" vs retime values 9.95s/10.43s → spinbutton hiển thị invalid. Fix: step="0.1" hoặc bỏ step.
#8. Picker: test projects (mini-loop-test, test-blank-project, agent-loop-test…) lẫn với projects thật. Jargon "SCAFFOLD v000 / EDIT v001". Fix: filter/section riêng + label thân thiện ("Draft", "Có video").
#9. Sources ẩn sau 3 tầng click (card → collapse → từng sub-question). YouTuber muốn scan links nhanh để trust. Fix: source list phẳng ở mức collapse đầu.
#10. Slug step riêng có thể gộp: auto-slug từ idea + edit nếu muốn.
#11. Header hiển thị nguyên đoạn idea dài (3 dòng) — nên rút gọn + tooltip.
#12. Finding research đầu tiên hiển thị raw code block (copy-paste demo) — nên truncate/pretty.

5. Tổng kết

Kết luận: Luận điểm cốt lõi của product ĐÚNG — từ một ý tưởng thô, trong ~45 phút (bao gồm 25 phút kẹt vì server cũ) có một video hook 36.8s có research thật, story có angle, script chuẩn formula, voice QC, và editor đầy đủ để tinh chỉnh. Phần "sinh nội dung" (research → story → script) hoạt động vượt mong đợi.

Nhưng: với user thật (không phải agent biết restart server), lần chạy đầu tiên hôm nay sẽ chết ở bước research và không tự phục hồi được. Ba fix CRITICAL trên là điều kiện để đưa cho user thật. Sau đó, efficiency của agent loop (MAJOR #4) quyết định trải nghiệm "agent làm giúp tôi" có đáng tiền không.

6. Bổ sung sau feedback (03:19) — Root cause "human sticker" + bài học audit

User bắt lỗ hổng mà walkthrough bỏ sót: nhân vật human sticker trong video bị gán cứng vào ảnh cũ của isaacverse-final.
Root cause nằm NGAY trong file text đọc được — characterPresence.ts:178: presenceAsset() hard-code isaacverse-final/character/poses/… cho MỌI project. Hai lỗ hổng chồng nhau:
(a) Ảnh cứng: project nào cũng render character bằng thư viện ảnh của isaacverse-final (ảnh từ 25/08). Asset Studio CÓ lưu poses per-project (<slug>/character/poses/) nhưng render path không bao giờ đọc chúng — poses user tạo là DEAD CODE.
